# MedRouter DSH runtime image

DeepSeek Harness (`dsh`) running as a long-lived agent service, with the
`dsh-api` plugin that MedRouter's **对话 (Chat)** page calls. The image bundles
the Office skills (PowerPoint / Word / Excel) and the Python libraries they
need, so a turn can produce a `.pptx`, `.docx` or `.xlsx` and hand it back for
download.

## Build

```sh
docker build -t medrouter-dsh:latest images/dsh
```

The chart defaults to `harbor.isuanova.com/suanova/medrouter-dsh`; push the
image there (or change `dsh.image.repository`) before installing with
`dsh.enabled=true`.

## What runs inside

| Path | Purpose |
|---|---|
| `/opt/dsh-seed` | Seed profile copied to the data volume on first start |
| `/opt/dsh-plugins/dsh-api` | The task API plugin (submit / poll / cancel / artifact download) |
| `/opt/dsh-plugins/medrouter-skills` | Medical/pharma and presentation skills (see below) |
| `/opt/dsh/overlay.yml` | Runtime overrides: bind address, model, sandbox, API options |
| `/data` | `DSH_HOME`, mounted from the chart's PVC |

On first start the entrypoint copies the seed profile into `DSH_HOME`, re-links
both in-image plugins (`dsh-api`, `medrouter-skills`), resolves the container's
eth0 address (dsh 0.2.2 refuses wildcard binds), and starts `dsh web`.

## User isolation

`dsh-api` never sees the end user's credentials. MedRouter authenticates the
browser session and sends the user id as `X-DSH-User-Id`; the plugin then

- puts each user under `<DSH_WORKSPACE>/<userId>` and refuses a `cwd` outside it;
- rejects continuation of another user's `sessionId` with `unknown_session`;
- filters task listing and fails closed on polling/cancel/artifact download for
  a task the caller does not own.

The chart shares the data volume with the MedRouter pod (mounted at
`/data/dsh` there) so uploads land in `<volume>/uploads/<userId>` and the agent
reads them at `/data/uploads/<userId>/...`.

## Bundled skills

`medrouter-skills` registers four on-demand skills next to the official Office
skills:

| Skill | Use |
|---|---|
| `slides-design` | 16:9 layout grid, type scale, palette, python-pptx tables/charts, visual QA |
| `medical-slides` | Study readouts, disease/product decks and medical education with sourced claims |
| `medical-writing` | Medical terminology, evidence language, citations, privacy, zh/en conventions |
| `pharma-trials` | Trial design, endpoints, analysis sets, safety reporting and bias traps |

Skills are instructions the model loads when a task matches; they are not tools.
The package is dependency-free and mounted by `overlay.yml`.

## Models

The runtime serves the platform's **own deployed inference services**, not a
fixed DeepSeek upstream. At container start the entrypoint asks MedRouter for
every `running` inference deployment (`MEDROUTER_MODELS_URL`, authenticated
with `DSH_API_KEY`) and writes `/data/runtime-models.yml`: one
`@deepseek-ai/dsh-llm-pi-ai` route per service.

| Variable | Default | Meaning |
|---|---|---|
| `MEDROUTER_MODELS_URL` | set by the chart | MedRouter's `/api/chat/runtime/models` |
| `DSH_LLM_BASE_URL` | private AI gateway `/v1` | OpenAI-compatible gateway in front of the services |
| `DSH_LLM_CONTEXT_WINDOW` | `32768` | Context window when the platform has no metadata |
| `DSH_LLM_MAX_TOKENS` | `8192` | Output cap for the same case |
| `DSH_MODEL_PROVIDER_PREFIX` | `mr-` | pi-ai provider id prefix; must match MedRouter |

The request body's `model` field (the service name) is what the platform's
Envoy AI Gateway routes on: its ext_proc derives the `x-ai-eg-model` header from
the body, so clients do not set that header themselves. When the running set
changes, MedRouter bumps a pod-template annotation on this Deployment; the
rollout regenerates the catalog.

## dsh-api configuration

Set through `dsh.agent.*` in the chart:

| Variable | Default | Meaning |
|---|---|---|
| `DSH_API_KEY` | generated by the chart | Shared secret for dsh-api and the catalog endpoint |
| `DSH_IMAGE_REVIEW_LIMIT` | `0` | Max `read_image` calls per task (0 = unlimited) |

`overlay.yml` sets the sandbox root to `/data/workspace`, the default preset to
`standard`, and the per-task budgets (20 min default, 2 h max, 10 min question
timeout). See the file for the full list.

## Health

`GET /api/v1/health` with `X-API-Key: <DSH_API_KEY>` returns
`{ok:true,data:{service:"dsh-api",...}}`. The chart's readiness/liveness probes
use it.
